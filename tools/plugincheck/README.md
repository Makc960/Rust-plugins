# plugincheck

Компиляция плагинов Roslyn'ом и проверка поведения без `Managed/` от игрового сервера.

`Managed/` в окружении разработки нет, поэтому игровое и Oxide API подменяется
заглушками в `stubs/`. Сигнатуры заглушек сверены с дампом
`исходники игры/Assembly-CSharp.cs` и `Oxide.Rust.cs`; в комментариях к полям
стоят номера строк первоисточника.

Это проверка компиляции и логики, а не замена прогону на живом сервере.

## verify_stubs.py — обязательный шаг

Заглушки пишутся вручную, и ошибка в них компилятору не видна: плагин
собирается здесь и падает уже на сервере. Ровно так и случилось —
`DamageTypeList` был объявлен в глобальном namespace вместо `Rust`, а у
`ItemDefinition` появилось поле `displayName_english`, которого в игре нет
вовсе.

```
python3 verify_stubs.py <каталог-дампа>
```

Скрипт сверяет каждый тип заглушек с дампом: namespace (с учётом вложенности
и одноимённых типов) и наличие каждого объявленного члена (с учётом
наследования). Возвращает ненулевой код, если есть расхождения. Запускать
после любой правки `stubs/`.

## Запуск

```
cp ../../AccountSystem.cs plugins/
cp ../../ServerMenu.cs    plugins/
dotnet run
```

`dotnet build` проверяет синтаксис и типы, `dotnet run` дополнительно гоняет
тесты из `harness/`:

* `Check.cs` — миграция данных версии 1 в трёхслойную модель: старые плоские
  счётчики уходят во «всё время», текущий вайп начинается с нуля, обратно
  старые ключи не пишутся.
* `Behaviour.cs` — сдвиг слоёв на `OnNewSave`, сдвиг окна активности по суткам,
  раскладка минут по часам через границу часа, лимит последних сессий,
  выбор любимого оружия и вытеснение из словарей с потолком.
* `Integration.cs` — сквозной сценарий: AccountSystem регистрирует вкладку в
  ServerMenu, она появляется в полосе `/menu`, SteamID64 доезжает payload'ом,
  профиль рисуется и убирается, карточка уровня на Главной цела.
* `Ui.cs` — вкладка профиля: payload `API_PrepareServerMenu`, команды подвкладок
  и периодов, отрисовка всех 7 подвкладок в 3 периодах, заглушка пустого
  прошлого вайпа, а также замер сборки экрана по `Stopwatch` на профиле с
  сотнями тысяч записанных событий.

Заглушки CUI в `stubs/Oxide.cs` не пустые: элементы реально складываются в
список, а `CuiHelper.AddUi` сериализует их в JSON, иначе замер времени сборки
экрана ничего бы не показывал.

## golden.sh — XSkinMenu без визуальных отличий

`./golden.sh` записывает эталон CUI с авторской версии плагина (базовый
коммит) и сравнивает с ним рабочую копию: 324 экрана × полный JSON каждого
`AddUi` и порядок `DestroyUi`, для игрока в нескольких состояниях (comfort,
права admin/vip, ImageLibrary). Любое расхождение печатается с контекстом.

Имена безымянных элементов в заглушке детерминированы (счётчик вместо GUID),
иначе транскрипт не сравнить; игроку эти имена не видны.

`XSkinHooks.cs` отдельно проверяет поведение горячих хуков — перекраску при
подборе, крафте и перемещении, ранние выходы и зеркало чёрного списка — и
запись данных: заглушка `DataFileSystem` хранит записанное в памяти и ведёт
журнал `Writes`, отложенные `timer.Once` собираются в `Timer.Scheduled` и
запускаются тестом через `Timer.Fire()`, так что видно, что и когда плагин
пишет на диск.
