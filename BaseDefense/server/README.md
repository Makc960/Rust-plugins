# Сервер магазина «Обороны базы» (оплата через Pally)

Через этот сервер игра продаёт VIP, командиров, камуфляжи и пропуск сезона, когда оплата идёт через
Pally, а не через RuStore Pay.

```
игра ──POST /api/order──▶ сервер ──счёт──▶ Pally
игра ◀── ссылка на оплату ──┘
игрок платит на странице Pally в браузере
Pally ──POST /pally/result (подпись токеном)──▶ сервер: заказ оплачен, покупка записана
Pally ──▶ страница /return ──кнопка «Вернуться в игру»──▶ игра спрашивает статус заказа и выдаёт покупку
```

- **API-токен Pally есть только на сервере**, в `/etc/basedefense-shop/shop.env` (права 600). Его нет
  ни в игре, ни в репозитории. Без токена нельзя ни выставить счёт, ни подделать уведомление об оплате.
- Игрока сервер знает только по **коду покупок**: 20 случайных символов, которые игра создаёт при первом
  запуске и показывает на экране VIP. Если ввести этот код на новом телефоне (кнопка «Ввести код с другого
  телефона»), туда переедут все покупки, а покупки нового телефона объединятся с ними. Старый код после
  этого тоже продолжает работать. Ни имени, ни почты, ни телефона сервер не хранит.
- Уведомление от Pally (если Result URL указывает на этот сервер) проверяется по подписи (MD5 от
  `OutSum:InvId:токен`). Без уведомления сервер сам спрашивает у Pally статус каждого неоплаченного заказа
  за последние сутки, поэтому покупка придёт, даже если игрок закрыл игру сразу после оплаты.
- «VIP на месяц» здесь не подписка: это +30 дней без автопродления. Если VIP ещё действует,
  дни прибавляются к сроку его окончания.

## Установка на VPS (Ubuntu или Debian)

Нужны: VPS с публичным IP, открытые порты 80 и 443, по желанию домен (например `shop.ваш-сайт.ru`,
A-запись на IP сервера). Без домена скрипт возьмёт адрес вида `1-2-3-4.sslip.io`, который сам указывает
на IP сервера, и HTTPS-сертификат будет выпущен на него.

```bash
git clone --depth 1 -b ccr-bdac1a50-wqgotp https://github.com/Makc960/Rust-plugins
sudo bash Rust-plugins/BaseDefense/server/deploy/install.sh shop.ваш-сайт.ru
```

Если домен — это уже работающий сайт на nginx этого сервера (например `ice-rust.store`), скрипт не
трогает сам сайт, а добавляет магазин по пути: `https://ice-rust.store/basedefense`. В конфигурацию сайта
вписывается одна строка `include /etc/nginx/snippets/basedefense-shop.conf;`, копия прежнего файла
сохраняется в `/var/backups/basedefense-shop`. Если nginx не примет новые настройки, всё вернётся как было.
Свой путь можно задать так: `install.sh ice-rust.store/shop`.

Ввести ID магазина и токен Pally заново: `sudo bash install.sh --pally`.

Скрипт:

1. ставит Node.js 22 (если нет Node 20 или новее) и Caddy, который сам получает и продлевает сертификат;
2. спрашивает **ID магазина** и **API-токен** из кабинета Pally (токен при вводе не виден) и сохраняет
   их в `/etc/basedefense-shop/shop.env`;
3. запускает службу `basedefense-shop` (systemd, отдельный пользователь, писать может только в
   `/var/lib/basedefense-shop`);
4. каждый день копирует базу покупок в `/var/backups/basedefense-shop` и хранит последние 30 копий;
5. в конце печатает адреса для кабинета Pally.

Если на сервере уже работает nginx, Caddy не ставится. Скрипт добавит магазин в nginx отдельным сайтом
(`/etc/nginx/conf.d/basedefense-shop.conf`) и получит для него сертификат через certbot, который потом
продлевает его сам. Остальные сайты на этом nginx не затрагиваются. Если порты занимает другой
веб-сервер, подключите магазин через него вручную, образец для nginx лежит в `deploy/nginx.conf`.

## Настройки в кабинете Pally

**Обычно ничего менять не нужно.** Сервер сам спрашивает у Pally, оплачен ли счёт: через 10 секунд
после заказа, потом каждые 20 секунд, с возрастом заказа реже, и так сутки. Адреса возврата игрока
(Success и Fail URL) сервер передаёт в каждом счёте сам.

**Если этот магазин Pally уже принимает оплату на сайте** (например, `ice-rust.store` и игра на одном
`shop_id` и токене), Result URL, Success URL и Fail URL в кабинете **не трогайте**: они нужны сайту.
Уведомления об оплате игровых заказов будут уходить на Result URL сайта. Сайт их не узнает (номера
заказов игры начинаются с `bd`), а игра получит покупку через проверку статуса.

Если магазин Pally нужен только игре, можно указать **Result URL** `https://ДОМЕН/pally/result`
(метод POST). Тогда покупки будут приходить сразу после оплаты, а не через несколько секунд.

Проверить, что сервер отвечает: откройте в браузере `https://ДОМЕН/health`, должно быть написано `ok`.
Проверить токен: `sudo basedefense-shop check`.

**Про домен.** Pally принимает адреса возврата (Success и Fail URL) только на домене сайта, указанного
в магазине Pally. Проще всего указать сайтом магазина адрес этого сервера. Если в магазине уже стоит
другой сайт, сервер это переживёт: когда Pally откажется принимать адреса возврата, сервер повторит
счёт без них и дальше будет создавать счета без них. Тогда после оплаты игрок вернётся в игру сам
(кнопкой «Назад» или из списка приложений), и игра сама спросит, прошла ли оплата. Даже если до сервера
не дойдёт уведомление Result URL, сервер сам спросит у Pally статус счёта, и покупка всё равно придёт.

## Сборка игры с этим магазином

Игра узнаёт адрес магазина при сборке:

```bash
./gradlew :app:assembleRelease -Pstore=rustore -PshopServer=https://ДОМЕН
```

В GitHub Actions адрес берётся из переменной репозитория `BASEDEFENSE_SHOP_SERVER`
(Settings → Secrets and variables → Actions → Variables). Это не секрет, а просто адрес. Без этой
переменной сборки идут с магазином на `https://ice-rust.store/basedefense`.

## Обслуживание

```bash
journalctl -u basedefense-shop -f        # журнал
systemctl restart basedefense-shop       # перезапуск после правки shop.env
cd Rust-plugins && git pull && sudo bash BaseDefense/server/deploy/install.sh   # обновление
```

Покупки игроков лежат в `/var/lib/basedefense-shop/db.json`. Время от времени копируйте его
(или папку `/var/backups/basedefense-shop`) куда-нибудь за пределы VPS.

### Если игрок пишет «оплатил, а покупка не пришла»

Попросите у него код покупок с экрана VIP, затем:

```bash
sudo basedefense-shop player ABCD-EFGH-IJKL-MNOP-QRST    # что у него есть
sudo basedefense-shop orders ABCD-EFGH-IJKL-MNOP-QRST    # его заказы и их статус
sudo basedefense-shop grant ABCD-EFGH-IJKL-MNOP-QRST commander_grom   # выдать вручную
```

Если заказ «ждёт оплаты», а деньги в кабинете Pally пришли, посмотрите журнал
(`journalctl -u basedefense-shop -n 100`): сервер мог не достучаться до Pally. После `grant` игроку достаточно открыть экран VIP или перезапустить игру. Товары:
`vip_month`, `vip_forever`, `starter_pack`, `commander_engineer`, `commander_grom`, `commander_sokolova`,
`skin_night`, `skin_parade`, `season_pass`.

## Для разработки

```bash
npm test                     # тесты, без сети и без Pally
PALLY_TOKEN=… PALLY_SHOP_ID=… PUBLIC_URL=https://… DATA_FILE=./db.json npm start
```

Всё, что зависит от API Pally (адрес, поля счёта, статусы, подпись уведомления), собрано в
`src/pally.mjs` и сверено со справкой Pally (бывший PayPalych): https://paypalych.com/en/reference/api.
Если Pally что-то поменяет, править нужно только этот файл.

| Метод | Путь                         | Что делает                                                   |
|-------|------------------------------|--------------------------------------------------------------|
| POST  | `/api/order`                 | `{code, product}` → `{order, url}`: счёт в Pally и ссылка     |
| GET   | `/api/order/:id?code=`       | `{status: pending\|paid\|failed, vipUntil?}`                  |
| GET   | `/api/purchases?code=`       | `{owned, vipUntil, passes}`: всё, что купил игрок            |
| POST  | `/api/move`                  | `{from, to}`: перенос покупок с кода `from` на код `to`       |
| POST  | `/pally/result`              | уведомление Pally об оплате (Result URL)                     |
| POST  | `/return`                    | страница после оплаты с кнопкой «Вернуться в игру» (и GET)   |
| GET   | `/health`                    | `ok`                                                         |
